# JIRA-1661: Add optional user job title

<!-- create-nodejs-express-app: implementation decision record -->

## Summary

Added an optional `jobTitle` profile field to users. It accepts strings up to 30 characters and is available when administrators create or update users and when users register.

## Changes made

- `src/models/user.model.js`
  - Added `jobTitle` as a trimmed Mongoose `String` with `maxlength: 30`.
  - Kept the field optional by omitting `required`.

- `src/validations/user.validation.js`
  - Allows `jobTitle` on user create and update requests using `Joi.string().max(30)`.

- `src/validations/auth.validation.js`
  - Allows `jobTitle` during registration using the same 30-character limit.

- `src/docs/components.yml`, `src/routes/v1/user.route.js`, and `src/routes/v1/auth.route.js`
  - Documented the field and its maximum length in the OpenAPI schema and request examples.

- `tests/fixtures/user.fixture.js`
  - Added a representative `jobTitle` to the primary user fixture.

- `tests/unit/models/user.model.test.js`
  - Added coverage for accepted job titles and rejected values over 30 characters.

- `tests/integration/user.test.js` and `tests/integration/auth.test.js`
  - Added create, update, registration, and response assertions for `jobTitle`.
  - Added API validation tests for values longer than 30 characters.

## Decisions

- `jobTitle` is optional so existing users and client requests remain valid.
- Values are trimmed in the model to avoid storing unintended leading or trailing whitespace.
- Mongoose and Joi both enforce the 30-character limit: Joi rejects invalid API input early, and Mongoose protects direct model usage.
- The field is available during registration as well as user administration, providing a consistent profile API.
- No controller or service changes were needed because validated request fields already flow through `User.create()` and `Object.assign(...); save()`.
- No migration is required because MongoDB/Mongoose stores schema additions without a relational migration.
